# Состояние работ — читать первым в новой сессии

Этот файл — точка входа. Работа идёт **по одному слайду за сессию**, каждый слайд
начинается с чистого диалога. Здесь лежит всё, что нужно, чтобы подхватить работу
без пересказа.

**Обновлять этот файл в конце каждой сессии.** Если он врёт, следующая сессия
начнётся с ошибки.

---

## Как начать сессию

1. Прочитать этот файл целиком.
2. Прочитать `docs/tz/01-SPEC.md` — **только раздел того слайда, над которым
   работаем.** Не весь файл, он большой.
3. Заглянуть в `docs/tz/03-QUESTIONS.md` — там вопросы по этому слайду с готовыми
   предложениями.
4. Запустить `npm run dev` → http://localhost:5173/
5. Работать. В конце — обновить раздел «Журнал» и «Текущий слайд» здесь.

Чего **не** надо делать в начале сессии: перечитывать `docs/HANDOFF.md` целиком,
пересматривать всё дерево `src`, заново разбирать `tz.docx`. Всё уже разобрано.

## Железные условия проекта

Нарушение любого = переделка.

1. **Только мобильная вёрстка.** Десктопа не будет вообще, это обязательное условие
   владельца. Проектная ширина 430px, проверять на 360px. Страница по горизонтали не
   скроллится никогда.
2. **Бэкенда не делаем.** Только макет. Кнопки оплаты — заглушки с `TODO`. В `api/`,
   `db/`, в плагин API внутри `vite.config.ts` не лезем. `DATABASE_URL` не нужен,
   `npm run db:init` не запускать.
3. **Тексты не сочиняем.** Всё берётся дословно из `01-SPEC.md`. Прошлый черновик
   программы был написан «по логике курса» и целиком выброшен — второй раз так не
   делаем.
4. **Ассеты не подменяем.** Если раскладка не сходится — меняем контейнер и CSS, а не
   картинку.
5. **Проверка перед сдачей:** `npm run typecheck`. Тестов в проекте нет, это
   единственная проверка, и она обязана быть зелёной.

## Что важно знать про код, чтобы не наступить дважды

Полный список грабель — в `docs/HANDOFF.md`, раздел «Грабли, на которые уже
наступили». Самое частое:

- ~~**`data-reveal` нельзя вешать на элемент с меняющимся `className`**~~ —
  неактуально с 31.08: анимация появления снята со страницы целиком (см.
  «Анимация появления» ниже).
- **Заголовки залиты через `background-clip: text`.** У «Й» пропадает бревис, если
  трогать `line-height` или вертикальные отступы `.section-title` / `.hero-title`.
  Компенсация уже стоит в `index.css`, ломать её нельзя.
- **Отступ между секциями — 52px**, задаётся классом `.section-rhythm`. Мерить надо
  по краске, а не по границам блоков, и только после прокрутки всей страницы:
  непроявленные `data-reveal` смещены на 24px и врут в замерах.
- **Трекинг Bebas — только целыми пикселями.** Токены `--tracking-title` и
  `--tracking-display`. В `em` шрифт замыливается.
- **`data-reveal` делает секцию контекстом наложения.** Он ставит `transform`, а
  любой transform, кроме `none` (включая `translateY(0)` в `.is-in`), отрезает
  внутренние z-index от внешних. `z-10` на контейнере внутри секции после этого
  бесполезен: общий свет `CourseBackdrop` (`z-[3]`) ложится поверх всей секции и
  глушит цвета — замер по пикселям кнопки давал зелёный 151 вместо 176, белый текст
  199 вместо 244. **z-index надо ставить на саму секцию**, как в «Программе».
- **`<main>` не должен становиться прокручиваемым.** У него `overflow-hidden`, и
  любой абсолютный слой, вылезший за низ внутренней обёртки, делает его внутренним
  скролл-контейнером. Браузер тогда прокручивает по якорю **его**, а не страницу:
  «К программе» уезжала внутри `main`, и вернуться к первому экрану колесом было
  нельзя. Лечится `overflow-hidden` на обёртке вокруг секций.
- **Плавная прокрутка (`scrollTo({behavior:'smooth'})`) не работает вместе с
  `snap-mandatory`.** Прилипание тянет ленту назад на каждом кадре анимации: клик по
  «вперёд» давал 15px вместо 280, три клика подряд — 0. Программную прокрутку делать
  присваиванием `scrollLeft`. Свайп пальцем анимируется сам и не страдает.
- **Индекс активной карточки нельзя брать только из события прокрутки.** Оно
  приходит на следующем такте, и быстрые нажатия по стрелке считали текущей
  предыдущую карточку. `goTo` ставит индекс сразу, `onScroll` — догоняет.
- **Tailwind не видит новые файлы, появившиеся после старта dev-сервера** — даже с
  директивой `@source "./"`, которая уже стоит. Проявляется молча: класс просто не
  генерируется. На слайде 6 из-за этого `size-[13px]` не существовал, и все галочки
  в карточках тарифов имели нулевую ширину — на экране их не было вовсе, а в разметке
  всё на месте. Завели новый файл — перезапустите `npm run dev`.
- **Проценты в `padding` считаются от содержащего блока, а не от самого элемента.**
  У ленты тарифов стоит `-mx-5`, то есть она на 40px шире секции, и честное
  `calc(50% - 131px)` давало поле на 20px короче нужного: крайние карточки не
  доезжали до центра (замер на 360: 22px слева против 61 справа). В формулу нужна
  поправка на вылет — `calc(50% + 20px - 131px)`, см. `SIDE_PAD` в `TariffsSection`.

## Анимация появления — снята

31.08 владелец попросил убрать всплытие блоков при скролле. Со страницы удалены
атрибуты `data-reveal`, класс `.reveal-child`, проп `index` у карточки модуля и
вызов `useReveal` в `App.tsx`. Сам хук `src/hooks/useReveal.ts` остался в
репозитории, но не вызывается ниоткуда.

**Возврата одним движением не будет:** без CSS-правил хук просто вешает класс,
на который ничто не реагирует. Чтобы вернуть, нужны и правила, и атрибуты.
Удалённый CSS — дословно:

```css
[data-reveal] {
  opacity: 0;
  transform: translateY(24px);
  transition:
    opacity 0.6s var(--ease-mass),
    transform 0.6s var(--ease-mass);
  transition-delay: var(--reveal-delay, 0ms);
}

[data-reveal].is-in {
  opacity: 1;
  transform: translateY(0);
}

/* Для элементов, чей className меняется по состоянию React: useReveal ставит
   .is-in через classList, а React при следующем рендере переписывает атрибут
   целиком, и элемент возвращается в opacity: 0. */
.reveal-child {
  opacity: 0;
  transform: translateY(24px);
  transition:
    opacity 0.6s var(--ease-mass),
    transform 0.6s var(--ease-mass);
  transition-delay: var(--reveal-delay, 0ms);
}

[data-reveal].is-in .reveal-child {
  opacity: 1;
  transform: translateY(0);
}

@media (prefers-reduced-motion: reduce) {
  .reveal-child { transition: none; }
}

@media (prefers-reduced-motion: reduce) {
  [data-reveal] { transition: none; }
}
```

Заодно ушла грабля, которая жила в проекте с самого начала: `data-reveal` нельзя
было вешать на элемент с меняющимся `className`, иначе блок исчезал при
перерисовке. Карточка модуля в «Программе» держалась на `.reveal-child` именно
поэтому.
