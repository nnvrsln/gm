## Работа по ТЗ — начинать отсюда

**Первым делом читай `docs/tz/05-STATE.md`.** Это точка входа: какой слайд в работе,
какие решения уже приняты, чего ждём от заказчика. Работа идёт по одному слайду за
сессию, каждый слайд — новый диалог.

- `docs/tz/01-SPEC.md` — расшифровка ТЗ по слайдам, дословные тексты. **Читать только
  раздел своего слайда**, файл большой.
- `docs/tz/02-TARIFFS.md` — тарифная сетка.
- `docs/tz/03-QUESTIONS.md` — открытые вопросы с готовыми предложениями.
- `docs/tz/04-PLAN.md` — этапы и маппинг «что переиспользуем, что выбрасываем».
- `docs/HANDOFF.md` — история дизайнерских решений и грабли. Не источник правды по
  содержанию, но грабли в силе.

Три условия, нарушение которых означает переделку:

1. **Только мобильная вёрстка.** Десктопа не будет вообще. 430px проектные, проверять
   на 360px, горизонтального скролла страницы быть не должно.
2. **Бэкенд не делаем.** Только макет; кнопки оплаты — заглушки. `api/`, `db/` и
   плагин API в `vite.config.ts` не трогать, `npm run db:init` не запускать.
3. **Тексты не сочинять.** Только дословно из `01-SPEC.md`.

Не переходить к следующему слайду, пока владелец не скажет «Переходи».

## Что это

Одностраничный лендинг предзаписи на онлайн-курс Гаджи Гаджиева: React 19 + Vite 7 +
Tailwind 4, форма заявки пишется в PostgreSQL через serverless-функцию `api/leads.ts`.
Весь интерфейс и все комментарии в коде — на русском.

## Команды

```bash
npm run dev        # Vite: фронт и локальный /api/leads на одном адресе (5173)
npm run db:init    # создаёт базу gm_course и применяет db/migrations/0000_initial.sql
npm run typecheck  # tsc --noEmit по src + отдельный проход по api (tsconfig.api.json)
npm run build      # typecheck, затем vite build
```

Тестов в проекте нет. `npm run typecheck` — единственная проверка перед коммитом;
она обязана быть зелёной, поскольку `build` её вызывает.

Перед первым запуском: скопировать `.env.example` → `.env.local`, подставить пароль
локального `postgres`, выполнить `npm run db:init`. Подробнее — `LOCAL_DEVELOPMENT.md`.

## Архитектура

**Два TypeScript-проекта в одном репозитории.** `tsconfig.json` покрывает `src` +
`vite.config.ts` (DOM lib, jsx), `tsconfig.api.json` — только `api/**` (без DOM).
Новый серверный код должен лежать в `api/`, иначе он не типизируется.

**API работает и локально, и на Vercel одним и тем же кодом.** `api/leads.ts` —
обычный `(VercelRequest, VercelResponse)`-хендлер. `vite.config.ts` содержит плагин
`localApiPlugin`, который импортирует этот хендлер напрямую и подкладывает ему
минимальный адаптер `ServerResponse → VercelResponse` (`setHeader`/`status`/`json`).
Если хендлеру понадобится другой метод VercelResponse — его нужно добавить в
`createVercelResponse`, иначе локально всё упадёт, а на проде будет работать.

**Секреты.** Vite грузит `.env.local` в `import.meta.env` (клиент), серверный код
читает `process.env`. Мост построен вручную в `vite.config.ts`: туда прокидывается
только `DATABASE_URL`. Новый серверный секрет надо явно добавить туда же — и ни в
коем случае не через префикс `VITE_`, иначе он уедет в бандл.

**База.** Drizzle-схема (`api/_lib/schema.ts`) и SQL-миграция
(`db/migrations/0000_initial.sql`) поддерживаются вручную и параллельно: drizzle-kit
не подключён, `scripts/migrate.mjs` просто прогоняет SQL-файл (идемпотентный,
`CREATE TABLE IF NOT EXISTS`). Меняя схему, правь оба файла.
Пул соединений создаётся лениво и кешируется в модуле; `max` = 1 под Vercel.

Таблицы `orders` и `payment_events` уже в схеме, но кода оплаты ещё нет — это
задел под интеграцию Prodamus (переменные `PRODAMUS_*` в `.env.example`).

**Валидация дублируется на клиенте и на сервере** — `src/components/LeadSection.tsx`
(`CHECKS`) и `api/leads.ts`. Регулярка телефона живёт в двух местах: `src/lib/phone.ts`
и константа `PHONE_RE` в `api/leads.ts`; формат `+7(999)000-00-00` должен совпадать.
Honeypot-поле `website`: если заполнено — сервер отвечает 201 и ничего не пишет.

## Фронтенд

- **Мобильный макет фиксированной ширины.** `App.tsx` оборачивает всё в
  `max-w-[430px]`; десктопной версии нет, верстать секции нужно под эту ширину.
- **Секции** — плоский список компонентов в `App.tsx`, каждая сама себе `<section>`
  с `px-5`. `SiteHeader.tsx` в дереве не используется, но оставлен намеренно.
- **Анимация появления** — атрибут `data-reveal` на секции + `useReveal` в `App.tsx`
  (один IntersectionObserver на всё дерево). Никаких библиотек анимации нет.
- **Дизайн-токены** — `@theme` в `src/index.css` (цвета `pitch/panel/blood`, шрифты,
  кривые `--ease-mass` / `--ease-snap`). Tailwind-конфига нет, всё через CSS.
- Комментарии в `index.css` фиксируют неочевидные решения с измерениями
  (трекинг Bebas только целыми пикселями, маски растворения краёв фото в px, а не в
  процентах). Перед правкой этих блоков — прочитать комментарий рядом.
- Шрифты локальные (`src/assets/*.ttf|woff2`), кроме мёртвой ссылки на Manrope из
  Google Fonts в `index.html` — она ни на что не влияет.
- Тексты-данные вынесены в `src/data/*.ts` (`ABOUT_CARDS`, `ACHIEVEMENTS`, аудитория),
  картинки импортируются в этих же файлах.

## Импорт конфигурации

В системе найден конфиг OpenAI Codex (`~/.codex/config.toml`). Если хочешь перенести
из него MCP-серверы, команды, агентов или инструкции — ответь `/import`: команда
покажет, что импортируемо, и выдаст digest; затем `/import --yes=<digest>` применит
пользовательские элементы.
