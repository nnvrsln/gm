# CLAUDE.md

Инструкции для Claude Code (claude.ai/code) по работе с этим репозиторием.

## Что это

Одностраничный лендинг онлайн-курса Гаджи Гаджиева: React 19 + Vite 7 + Tailwind 4.
Весь интерфейс и все комментарии в коде — на русском.

**Макет закончен.** Слайды 1–6 и 8 свёрстаны, слайды 7 и 9 сняты — контента по ним
заказчик не дал. Текущий этап — **бэкенд**: приём оплаты и передача заявок в CRM.

## Текущий этап: бэкенд

**Читать первым делом `docs/tz/06-BACKEND.md`** — там стек, схема БД, контракты
эндпоинтов, карта полей amoCRM, развёртывание и порядок работ. Ниже — только вводная.

Сейчас серверной части в репозитории нет вообще: в `dependencies` только `react` и
`react-dom`, ни одного `fetch` из кода, ни `.env`. Кнопки оплаты — заглушки «Скоро».

Стек согласован 02.09.2026: **Fastify 5 + Zod + PostgreSQL 17 + Drizzle + pg-boss**,
Docker Compose за Caddy. Что отвергнуто и почему — в разделе «Стек» того же файла;
там же записано, что NestJS, SQLite, Prisma и BullMQ повторно не предлагаются.

Что предстоит:

- создание заказа: полная оплата и бронь за 10 000 ₽ (`PayAction` в `data/tariffs.ts`);
- платёжная форма Prodamus + вебхук о зачислении с проверкой подписи;
- передача заявок и сделок в amoCRM;
- хранение заявок, заказов и событий оплаты.

Два правила, нарушение которых означает переделку:

1. **Сумму считает только сервер.** Клиент присылает `{ tariffId, action }`, не рубли.
2. **Вебхук идемпотентен.** Платёжки шлют дубли: сначала проверка подписи, потом
   запись события с уникальным ключом, и только потом всё остальное.

Схема БД под заказы уже была написана на Drizzle и удалена вместе с прежним
бэкендом. Поднимается из git: `git show 37c81ea:api/_lib/schema.ts`, там же
`db/migrations/0000_initial.sql` — в ней есть `payment_events.event_key UNIQUE`
под ту самую идемпотентность.

## Команды

```bash
npm run dev        # Vite на 5173
npm run typecheck  # tsc --noEmit по src и vite.config.ts
npm run build      # typecheck, затем vite build
```

Тестов в проекте нет. `npm run typecheck` — единственная проверка перед коммитом;
она обязана быть зелёной, поскольку `build` её вызывает.

Отдельный инструмент: `node scripts/to-webp.mjs [файл…]` — перегоняет PNG из
`src/assets` в WebP. Не часть сборки, гоняется руками, когда заказчик приносит новые
кадры.

Папка `.git` принадлежит другому пользователю Windows, поэтому git ругается на
dubious ownership. Обход без правки глобального конфига:


## Архитектура

**Один TypeScript-проект.** `tsconfig.json` покрывает `src` и `vite.config.ts`.
Серверный код появится вторым проектом — прежний `tsconfig.api.json` удалён вместе
с `api/`.

**Сборка — одна страница.** `index.html` → `src/main.tsx` → `App.tsx`. Макетные
страницы, на которых примерялись подачи слайдов, удалены; если понадобится новая,
она заводится парой «`имя.html` в корне + `src/имя.tsx`» и в прод-сборку не
попадает (Vite по умолчанию берёт единственной точкой входа `index.html`).

**Секретов и переменных окружения сейчас нет.** Появится серверный секрет — его
нельзя добавлять с префиксом `VITE_`, иначе он уедет в бандл.

## Фронтенд

- **Мобильный макет фиксированной ширины.** `App.tsx` оборачивает всё в
  `max-w-[430px]`; десктопной версии нет, верстать секции нужно под эту ширину.
- **Секции** — плоский список компонентов в `App.tsx`, каждая сама себе `<section>`
  с `px-5`. Шапки нет: навигация по секциям живёт в подвале.
- **Анимации появления секций нет** — снята 31.08 по просьбе владельца. Библиотек
  анимации в проекте нет вообще.
- **Прокрутка по якорям плавная** (`scroll-behavior: smooth` под
  `prefers-reduced-motion`). Важно: слой `CourseBackdrop` обязан лежать внутри
  клипующей коробки по размеру обёртки — иначе обёртка становится прокручиваемой, и
  переход по якорю уносит содержимое секций вверх.
- **Дизайн-токены** — `@theme` в `src/index.css` (цвета `pitch/panel/blood`, шрифты,
  кривые `--ease-mass` / `--ease-snap`). Tailwind-конфига нет, всё через CSS.
- Комментарии в `index.css` фиксируют неочевидные решения с измерениями
  (трекинг Bebas только целыми пикселями, маски растворения краёв фото в px, а не в
  процентах). Перед правкой этих блоков — прочитать комментарий рядом.
- Шрифты локальные (`src/assets/*.ttf|woff2`), внешних запросов со страницы нет.
- Тексты-данные вынесены в `src/data/*.ts` (`ACHIEVEMENTS`, аудитория, программа,
  тарифы, FAQ, правовые ссылки), картинки импортируются в этих же файлах.
- `src/data/tariffs.ts` не импортирует ничего — ни React, ни ассетов. Это сделано
  намеренно: серверный код может импортировать его напрямую и брать цены оттуда,
  чтобы таблица цен не дублировалась.
- В `src/assets` лежат только используемые файлы: каждый ассет оттуда попадает
  в сборку.
